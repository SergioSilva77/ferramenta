# 06 - rpaflow v2

`rpaflow.v2` é uma cópia corrigida das classes originais. **Nada do v1 foi alterado** — projetos antigos continuam
funcionando; projetos novos (ou migrados) importam de `rpaflow.v2`.

```python
from rpaflow.v2 import ExcelCom, Browser, SQL, Email, Excel, Files, Ini, Json, Log, API, Desktop
```

Os módulos carregam sob demanda: `import rpaflow.v2` não exige playwright, pywin32, loguru etc.

## Migração

Em geral basta trocar o import. Mudanças de comportamento a conhecer:

| Onde | v1 | v2 |
|------|----|----|
| `ExcelCom()` | `Dispatch`: agarra o Excel que já estiver aberto | Excel **próprio** (`DispatchEx`). `ExcelCom(isolated=False)` volta ao comportamento antigo |
| `ExcelCom.quit()` / `with` / `del` | `close()` nunca fechava o Excel; ele sobrava aberto | fecha o processo desta instância (e só ele). Se o Python morrer, a próxima execução limpa só aquele PID |
| `ExcelCom.get_last_row/col` | `UsedRange.Rows.Count` | número real da última linha/coluna |
| `ExcelCom.find_row` | colunas inexistentes ignoradas | `KeyError` |
| `ExcelCom.read_range_filtered` | filtro com coluna inexistente ignorado | `KeyError` |
| `Browser.start(type="selenium")` | aceitava, mas nenhum método funcionava | `BrowserError` |
| `Browser.start()` duas vezes | vazava o primeiro navegador | `BrowserError` (chame `close()` antes) |
| `Excel("x.xlsx").open()` com arquivo inexistente | criava planilha vazia em silêncio | `FileError` (use `create_if_missing=True`) |
| `Files.dir_get_dirs` | só o nome | caminho completo |
| `Files.dir_get_files` / `dir_get_all_files` | incluíam pastas | só arquivos |
| `SQL.update/delete` sem `where` | rodavam na tabela inteira | `ValueError` |
| `Json()` | `default_box=True` fixo | parâmetro `default_box` (padrão igual) |

## Bugs corrigidos (todos com teste em `tests/v2`)

### Em comum
- Exceções (`BrowserError`, `QueryError`, `EmailError`, `FileError`, `APIError`) nunca eram importadas nos módulos
  que as levantavam: **qualquer falha virava `NameError`** e escondia o erro real.

### ExcelCom
- `Dispatch` compartilhado: o `Quit()` de um robô fechava as planilhas do outro (`disconnected from its clients`).
- Sem `quit()` efetivo / `__del__` / `with`: Excel órfão para sempre.
- `clear_filters`: chamava `tbl.Range.ShowAllData` (não existe), o `except: pass` engolia — nenhum filtro era limpo.
- `wait_calculation`: método COM inexistente (`...AsyncQueriesStop`; o certo é `...Done`).
- `list_hidden_sheets/count_hidden_sheets`: sheet *very hidden* contava como visível.
- `set_sheet_visible(-2)`: valor inválido para "very hidden" (o certo é 2).
- `find_row`: `.replace(".0", "")` virava `"10.05"` em `"105"`; coluna inexistente casava a linha 0.
- `read_range_filtered` / `read_filtered_table`: `Rows.Hidden` em range misto devolve `False`; linhas filtradas
  vinham no resultado. `UsedRange` deslocado dava última linha errada.
- `filter_column_values` com número/data estourava (AutoFilter por lista só aceita texto).
- `filter_pivot_values` podia deixar a dinâmica sem item visível no meio da operação.
- `select_cell` deixava o Excel visível para sempre; `copy_values` deixava o modo "formigas marchando" se falhasse.
- `save_as` com extensão diferente do formato atual (ex.: `.csv`) gerava arquivo errado.
- `read_table_column`/`count_table_rows` em tabela vazia estouravam.
- Novos: `set_pivot_source` (fonte da dinâmica = nome da tabela, cresce com os dados), `refresh_pivot_caches`.

### Browser
- `wait_for_download` abria o `expect_download` e saía do bloco: o evento (disparado antes) era sempre perdido.
- `wait_for_element(state="hidden", recursive=True)` procurava um elemento *visível* para esperar sumir.
- `close_tab` só funcionava por acidente; abas de popup não eram observadas.
- Modo CDP (`cdp_port=`): Chrome nativo com porta e perfil próprios; `close()` encerra só o Chrome daquele perfil
  (casamento exato de `--user-data-dir`, `User Data - RPA` ≠ `User Data - RPA Outro`).

### SQL
- INSERT/UPDATE/DELETE em SQL Server/PostgreSQL: `fetchall()` sem resultado dava erro e disparava **ROLLBACK** —
  o dado nunca era gravado.
- Cursor nunca fechado; `rollback` falhando mascarava o erro da query.
- `LIKE '%x%'` sem parâmetros estourava no pymysql (agora não passa lista vazia).
- Nomes de tabela/coluna concatenados crus (agora validados).

### Ini / Json / Files
- `Ini`: `%` em senha (`InterpolationSyntaxError`), BOM (`MissingSectionHeaderError`), valor vazio em `get_int`.
- `Json`: lista no topo (`Box(lista)` estourava), BOM, acentos escapados só às vezes, tipos não serializáveis.
- `Files`: `get_base_directory` devolvia o cwd (no Agendador de Tarefas é `System32`), `[` no caminho quebrava o
  `glob`, `set_attributes(hidden=)` ignorado, `change_extension("x", "log")` estourava.

### Log / Email / Excel (openpyxl) / API / Desktop
- `Log`: `logger.remove()` apagava os handlers de **todos** os `Log` do processo.
- `Email`: lista de destinatários numa string ia como um endereço só; anexo com o caminho inteiro do Windows como nome.
- `Excel.write()` **sempre estourava** (`ws["A1"].min_row` não existe); `read("A1")` devolvia célula.
- `API`: sem `params`, sem `timeout` útil, sem redirect, 4xx/5xx passavam como sucesso.
- `Desktop`: `ImageNotFoundException` do pyautogui novo derrubava na primeira tentativa.
